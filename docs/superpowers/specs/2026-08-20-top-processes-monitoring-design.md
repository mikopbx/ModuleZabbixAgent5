# Спецификация: мониторинг топ-10 процессов по CPU и памяти

Дата: 2026-08-20
Статус: утверждён вариант «UserParameter-скрипт» (вариант 2), реализация поручается субагенту.

## 1. Цель

Дать администратору MikoPBX возможность через Zabbix видеть, какие процессы на АТС
потребляют больше всего оперативной памяти и CPU, чтобы находить неоптимально
работающие «виновники». История снимков хранится в Zabbix — можно отмотать к
моменту инцидента.

## 2. Решение в двух словах

Две новые функции в `bin/asterisk-stats.sh` (`topMem`, `topCpu`), вычисляющие
топ-10 процессов прямо на АТС и отдающие компактный текст; два новых текстовых
айтема в шаблоне `bin/zbx_export_templates.yaml`. Нативный `proc.get` отвергнут:
он гоняет JSON по всем процессам на сервер при каждом опросе и отдаёт CPU как
накопленное время, а не процент. LLD-дискавери процессов отвергнуто: состав
топ-10 постоянно меняется и порождает шквал created/deleted айтемов.

в `Lib/ZabbixAgent5Main.php` не трогать. PHP-код не затрагивается вообще.

## 4. Контракты репозитория (CLAUDE.md), которые обязан соблюдать исполнитель

- Скрипты в `bin/` исполняются `/bin/sh` на BusyBox: никаких bash-измов
  (никаких массивов, `[[ ]]`, `<()`, `local -n`); там, где в файле уже используются
  явные апплеты (`/bin/busybox ps`, `/bin/busybox cat`), новый код следует тому же стилю.
- Арность UserParameter не меняется: `topMem`/`topCpu` не принимают аргументов
  и вписываются в существующую диспетчеризацию.
- Каждый новый `uuid:` в `bin/zbx_export_templates.yaml` — dashless 32-hex UUIDv4:
  13-й символ `4`, 17-й символ один из `8/9/a/b`. Один невалидный UUID ломает
  импорт всего шаблона. UUID генерировать, например:
  `python3 -c "import uuid; print(uuid.uuid4().hex)"` (выполнить дважды).
- Бинарники агента не добавлять; сгенерированный JS не трогать (JS в задаче не участвует).

## 5. Дизайн `topMem`

Один проход awk по `/proc/[0-9]*/status`, сортировка, топ-10:

```sh
# Top 10 processes by resident memory (RSS)
topMem(){
    /bin/busybox awk '
        /^Name:/  {name=$2}
        /^Pid:/   {pid=$2}
        /^VmRSS:/ {printf "%d %s %s\n", $2, pid, name}
    ' /proc/[0-9]*/status 2>/dev/null \
    | /bin/busybox sort -rn \
    | /bin/busybox head -n 10 \
    | /bin/busybox awk '{printf "%.1fM %s %s\n", $1/1024, $3, $2}'
}
```

Формат вывода — по строке на процесс, отсортировано по убыванию RSS:

```
512.3M asterisk 1234
48.7M php 5678
...
```

Точный порядок полей: `RSS_в_МБ ИМЯ PID` (имя перед PID — читабельнее в Latest data).
Kernel-threads без VmRSS отсекаются автоматически (строка VmRSS у них отсутствует).
`2>/dev/null` обязателен: процессы умирают между glob и чтением файла.

Примечание для исполнителя: проверить на BusyBox awk, что переменные `pid`/`name`
корректно сбрасываются между файлами (в `/proc/*/status` `Name:` всегда идёт первой
строкой, `Pid:` — до `VmRSS:`, поэтому перенос значений между файлами невозможен;
но это надо подтвердить на реальном выводе).

## 6. Дизайн `topCpu`

Два замера `/proc/[0-9]*/stat` с интервалом 1 секунда; процент считается как
дельта (utime+stime) процесса, делённая на дельту суммарного времени всех CPU из
`/proc/stat`, ×100. Нормировка — на суммарную дельту по всем ядрам, т.е. 100% =
полная мощность всех ядер (режим «Irix off» в терминах top). Это осознанный
выбор — зафиксировать его в описании айтема.

Алгоритм:

1. Снять `sample1`: для каждого `/proc/<pid>/stat` — `pid`, `comm`, `utime+stime`
   (поля 14 и 15); плюс сумма всех полей первой строки `/proc/stat` (total jiffies).
2. `sleep 1` (BusyBox sleep).
3. Снять `sample2` тем же способом.
4. Для PID, присутствующих в обоих замерах:
   `cpu% = (delta_proc / delta_total) * 100`.
5. Отсортировать по убыванию, вывести топ-10 строками `CPU% ИМЯ PID`,
   процент с одним знаком после запятой.

Критическая ловушка парсинга: поле 2 в `/proc/<pid>/stat` — `(comm)` — может
содержать пробелы и скобки (например `(tmux: server)`). Парсить нельзя простым
`awk '{print $14}'`. Обязательный приём: имя — всё между первой `(` и **последней**
`)`; числовые поля считать от последней `)` (после неё поле state — №3, значит
utime — 11-е поле после скобки, stime — 12-е). В awk: `match($0, /\(.*\)/)` +
`substr`, остаток разбить `split`.

Реализация — одна awk-программа, вызываемая дважды (замеры пишутся во временные
файлы в `/tmp` с PID скрипта в имени и удалением через `trap`/в конце), либо
две порции данных склеиваются и обрабатываются одним awk в END-блоке. Выбор за
исполнителем; критерии: BusyBox awk, отсутствие гонок при параллельных опросах
(два одновременных запроса агента не должны портить файлы друг друга — поэтому
`$$` в имени временных файлов обязателен), общее время выполнения < 2 секунд.

Ограничение по времени: у агента `Timeout=3` (закомментированный дефолт в
`bin/zabbix_agentd_default.conf`, т.е. действует 3 секунды). Интервал замера —
строго 1 секунда; суммарное время функции держать заметно ниже 3 с. `Timeout`
в конфиге НЕ увеличивать.

Формат вывода:

```
42.3% asterisk 1234
7.1% php 5678
...
```

## 7. Изменения шаблона `bin/zbx_export_templates.yaml`

Два айтема внутри существующего шаблона `MikoPBX monitoring` (формат экспорта
`6.4` не меняется), по образцу существующих текстовых айтемов (`value_type: TEXT`):

| Поле | Айтем 1 | Айтем 2 |
|---|---|---|
| key | `asterisk[topMem]` | `asterisk[topCpu]` |
| name | `MikoPBX: Top 10 processes by memory` | `MikoPBX: Top 10 processes by CPU` |
| value_type | TEXT | TEXT |
| delay | 5m | 5m |
| history | 7d | 7d |
| uuid | новый валидный UUIDv4 | новый валидный UUIDv4 |

В `description` каждого айтема — формат строк вывода; для topCpu дополнительно:
«100% = суммарная мощность всех ядер; замер за 1-секундный интервал в момент опроса».
Триггеры не добавляем (YAGNI): инструмент диагностический, смотрится через
Latest data / History.

## 9. Верификация (обязательна перед завершением)

1. `sh -n bin/asterisk-stats.sh` — синтаксис.
2. Прогон функций на реальном BusyBox-окружении: docker-контейнер MikoPBX
   (skill `container-inspector` даёт параметры подключения). Как минимум:
   `topMem` возвращает 10 строк с убывающими значениями; `topCpu` возвращает
   строки с процентами и укладывается по времени (`time …` < 2 с); процесс с
   пробелом в comm не ломает вывод. Если контейнер недоступен — прогнать awk-логику
   через `busybox sh`/`busybox awk` локально (macOS: `docker run --rm busybox`)
   и явно отметить в отчёте, что на реальной АТС не проверялось.
3. Валидация всех UUID шаблона (включая новые) — однострочник:
   `grep -oE 'uuid: [0-9a-f]{32}' bin/zbx_export_templates.yaml | awk '{u=$2; if (substr(u,13,1)!="4" || index("89ab",substr(u,17,1))==0) print "BAD", u}'` — пустой вывод.
4. YAML-валидность: `python3 -c "import yaml,sys; yaml.safe_load(open('bin/zbx_export_templates.yaml'))"`.
5. `diff bin/asterisk-stats.sh Setup/zabbix/scripts/asterisk-stats.sh` — единственное
   содержательное отличие: строка `PHP_INFO` (см. п. 3.2); прочих расхождений нет.
6. PHPStan не требуется — PHP не изменяется (если исполнитель всё же коснётся PHP,
   обязателен `phpstan --memory-limit=1G`).
